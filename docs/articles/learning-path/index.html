アーキテクチャを、
どの順番で学ぶか。

パターン名を集めるより、問いの解像度を少しずつ上げる。全体像からコード、依存方向、継続的検証、難しい判断へ進む5冊の読書ルートです。

先に結論

Clean Architectureから始めなくてよい。まずアーキテクチャ全体の語彙を得て、コード上の境界を見られるようになってから依存原則を読むと、円の暗記になりません。

この記事の流れ

  1. 全体の地図
  2. コードの境界
  3. 依存方向
  4. 継続的検証
  5. 難しい判断
1 / 5 — 全体の地図を持つ

最初に、設計を話すための共通語彙を得る。

最初の疑問は「どのパターンを使うか」ではなく、「アーキテクチャは何を決める仕事か」です。品質特性、モジュール性、結合、凝集、アーキテクチャスタイル、トレードオフという語彙がないまま個別手法を読むと、すべてがルール集に見えます。

1冊目

ソフトウェアアーキテクチャの基礎

変更容易性、性能、可用性などの品質特性と、レイヤード、イベント駆動、マイクロサービスなどの選択を広く扱う。

この段階では、スタイルごとの細かな比較を覚える必要はありません。「設計判断には複数の力が働き、ひとつの正解はない」と説明できれば次へ進めます。

2 / 5 — コードで境界を見る

抽象的な原則を、日常のクラスとパッケージへ降ろす。

全体像の次は、変更を局所化するコードがどのように見えるかを学びます。業務ルールとデータをまとめる、技術都合を境界の外へ出す、巨大なServiceや便利な共通処理を分解する、といった判断です。

2冊目

現場で役立つシステム設計の原則

日本語の業務システム例を通して、オブジェクト、パッケージ、データベース、画面の設計を変更容易性へ結びつける。

すべての例をそのまま採用するのではなく、「この分割は、どの変更をどこへ閉じ込めるのか」と問いながら読みます。自分のコードで、変更理由が異なるのに同じ場所へ置かれたものを見つけられれば十分です。

技術評論社の公式ページを開く

3 / 5 — 依存方向を理解する

ここで初めて、Clean Architectureを読む。

前の2冊で「守りたい変更理由」が見えるようになると、Dependency Inversion、Stable Dependencies、Entities、Use Casesが何のためにあるかを判断できます。中心は4つの円ではなく、ポリシーが技術詳細の名前を知らない依存方向です。

3冊目

Clean Architecture

SOLIDからコンポーネント原則まで、ビジネスルールを詳細から守る依存構造を説明する。

層の名前やinterfaceの数を規則として写さないことが重要です。「この境界は異なる変更理由を分けるか」「内側が外側の都合を知っていないか」を読み取ります。具体的な読み方は、この連載のClean Architecture記事で段階的に説明しています。

KADOKAWAの公式ページを開く

4 / 5 — 継続的に守る

設計原則を、CIで観測できる条件へ変える。

依存方向を理解しても、日々の変更で構造はずれます。そこで「良い設計」を、循環がない、許可外の依存がない、公開面が増えすぎない、といった検証可能なfitness functionへ変換します。

4冊目

進化的アーキテクチャ

一度決めた設計を固定するのではなく、漸進的な変更へ適応しながら重要な特性を守る方法を扱う。

archscoreはこの考え方を、依存グラフのfitness functionとして実装しています。読後には、設計レビューで使う言葉をひとつ選び、「CIで観測するなら、どんな入力と失敗条件になるか」を書いてみると理解が定着します。

5 / 5 — 正解のない判断を練習する

最後に、分割が別の複雑さを生む場面を読む。

境界を増やせば疎結合になるとは限りません。モノリスを分けると、データ所有、通信、トランザクション、障害、デプロイ順序という新しい結合が生まれます。ここでは原則の適用ではなく、複数案の損得を比較する力が必要です。

5冊目

ソフトウェアアーキテクチャ・ハードパーツ

サービス境界、共有データ、ワークフロー、同期・非同期通信など、分散アーキテクチャの難しい判断をトレードオフとして扱う。

実際にモノリスを分割する段階なら、続けて『モノリスからマイクロサービスへ』を読むと、段階的移行とデータ分割を具体化できます。

まとめ

本の順番は、問いの順番。

全体の語彙を得る。コードで境界を見る。依存方向を理解する。ルールを継続検証する。最後に、分割が生むトレードオフを考える。この順なら、パターン名ではなく設計判断が積み上がります。

2冊だけ選ぶなら

『ソフトウェアアーキテクチャの基礎』と『現場で役立つシステム設計の原則』。その後、依存方向へ進むなら『Clean Architecture』、測定とCIへ進むなら『進化的アーキテクチャ』を選びます。
